YOUR BUILD / THE FIRST TARGET

Start curious.
Choose deliberately.

NIX is being designed for custom x64 desktops. The initial engineering target is one defined machine profile: CPU, motherboard, GPU, storage, networking, audio, and USB controllers. That narrow scope gives each driver and recovery path a concrete place to be tested.

01

Planning your first PC?

Start with the tasks you care about: writing, creative work, gaming, or development. Learn how CPU, memory, graphics, and storage choices serve those tasks. Follow NIX’s hardware work before buying parts specifically for it.

02

Already built your rig?

Keep a device inventory, including exact controller and GPU models. A familiar connector or CPU architecture alone does not establish driver support.

03

Want to build NIX itself?

Explore the Core source and the delivery plan. The most useful foundation is reproducible boot, clear diagnostics, and changes that can be checked on the selected target.

05 / CORE & HARDWARE

A narrow hardware target.
A deliberate driver plan.

MilestoneRequired piecesCompletion gate
Boot & recoveryUEFI loader, framebuffer handoff, serial diagnostics, ACPI tables, page tables, allocator, interrupts, timers, SMP, recovery imageRepeatable boot on the selected machine; crash diagnostics and recovery without AI
Usable prompt interfaceUSB xHCI + HID keyboard/mouse, PCIe, NVMe/AHCI storage, persistent filesystem, Ethernet, compositor and basic display outputPrompt input, durable saves, restart, offline prompt interface, supported network adapter
Local AIModel loader, tokenizer, CPU inference backend, memory budgeting and cancellation; later supported GPU compute driver/runtimeLocal intent processing with network disabled and measured latency/RAM use
VirtualizationIntel VT-x or AMD-V, nested paging, vCPU lifecycle, guest interrupts, IOMMU, device models, storage/network/display channelsA guest boots and remains isolated; Pod crash does not crash the NIX interface
Gaming & XRGPU acceleration, graphics API/runtime, audio, game controllers, headset transport, tracking, display timing and an XR runtimePer-device graphics and latency tests; per-game compatibility results

Prefer restartable user-space drivers where practical. Core retains privileged interrupt and memory-mapping primitives; the driver broker grants narrow MMIO, IRQ, and DMA capabilities. DMA isolation requires configured IOMMU mappings.

UEFI boot drivers do not replace runtime storage, networking, USB, or GPU drivers after the OS takes over. Existing Linux/Windows drivers require porting or a guest path. A basic framebuffer can display the first prompt; accelerated AI, games, and XR need a separate driver effort.

BEFORE YOU SWITCH

A working recovery path
belongs in every build.

Keep your current working environment and backups while exploring NIX. The hardware roadmap will define what has been validated. Broad support comes from repeatable tests on named devices, one profile at a time.
